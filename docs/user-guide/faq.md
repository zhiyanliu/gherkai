# 常见问题

本页收的是**决策前的疑问**：还没进入某个具体任务，或者答案要素分散在两页以上的问题。手里已经是一个任务（装、写用例、运行、部署）请直接看对应的任务页；手里是一条报错或症状请看[排错](./troubleshooting.md)。答案完整落在某一页某一节的问题不收在这里——从[本指南首页的主题表](./README.md)一步就能找到那一页。

### 和 Playwright、Cucumber 是什么关系？现有用例能迁过来吗？

gherkai 不是它们的插件，也没有迁移命令：`.feature` 的语法基本通用（少数写法不支持），但 Cucumber、behave 的 step definitions 不会被认成 gherkai 的确定性 step（注册要用 gherkai 自己的 API），已有的 Playwright 代码可以搬进确定性 step——handler 拿到的就是 Playwright 的页面对象。两套框架能在同一个仓库里各用自己的命令运行，只是别让别的框架的 Python step 文件落进 gherkai 读的 `steps/`（那里任一文件加载失败会让整批无法运行），必要时用 `--steps-dir` 把 gherkai 指到别处。见[编写 .feature](./writing-features.md#gherkin-写法的支持范围)。

### 必须用 AWS 吗？能不能接自己的模型 API key？

必须有 AWS 账户。两个引擎用的模型都在 AWS 的托管模型服务上、走 AWS 凭证鉴权，没有填第三方 API key 的地方，换模型也只能换成这些服务上受支持的模型。承载浏览器会话的同样是 AWS 的托管服务，所以在本机运行也需要凭证。见[配置](./configuration.md#模型选择)。

### 它在什么浏览器里运行？能测移动端视口，或换成 Firefox、Safari 吗？

不能换浏览器，也没有视口旋钮。浏览器是云端托管的 Chromium 会话（每个 scope 一个），命令选项与环境变量里都没有浏览器种类、窗口尺寸或设备模拟这类设置，被测对象只能是浏览器打得开的 Web 应用。要按窄视口验收，可以让被测应用走它的移动版入口。见[开始使用](./getting-started.md#aws-前置)。

### 想先试一下，必须先在 AWS 里部署一整套云端后端吗？

不必。默认的本机跑法只要装好命令行和要用的引擎 worker、本机有 AWS 凭证就能完整运行一批，`gherkai plan` 连凭证都不需要、也不产生费用。云端后端只在团队要共享一套执行环境、提交完就关机时才需要，由部署方一个人建与维护。见[运行测试与查看结果](./running-and-results.md#两个独立的选择怎么运行在哪运行)。

### 什么时候该从本机运行换成云端后端？

判据是两条：提交完想不想关机、结果要不要团队共享。本机运行要求发起的机器一直在线、结果落在这台机器的报告目录里；用 `submit` 提交到云端后端后即可关机（`run --backend cloud` 仍要本机的命令进程在线），状态与产物落在共享的表与桶里，同事和 CI 读的是同一套。代价是要有人维护这套后端，并让每台机器的命令行版本与它保持一致。见[部署与维护云端后端](./cloud-backend.md#后端包含什么)。

### AI 做出的判定能当回归门禁吗？同一条用例会不会今天过、明天不过？

能当门禁，前提是按可信度分层写用例：必须精确、不容许波动的检查落成确定性 step，页面级语义交给 AI 断言并用投票判多次取多数。默认模型固定在一个具体版本、不会自动跟随最新，换默认模型只随命令行发版；自己换模型或升级命令行后，先用同一批用例对照一遍再当门禁。见[编写 .feature](./writing-features.md#ai-断言怎么写才稳)。

### 能不能整条用例都不走 AI，当普通端到端测试用？

可以。每一步都命中确定性 step 的用例不调模型、不投票，判定与耗时照常进判定明细，退出码照常表判定。代价是这些步不产生 AI 证据（没有轨迹或回放页可看），而云端浏览器会话仍照常建立，这部分费用不省。见[编写确定性 step](./writing-deterministic-steps.md#写之前)。

### 需要登录才能看到的页面怎么测？多条用例怎么共用一次登录？

把要接续的 scenario 标成同一个 `@scope`：它们共享一个浏览器会话、按书写顺序串行执行，第一条完成登录，后面几条直接接着用。填凭据这一步写成确定性 step，由它从环境变量读；点开登录入口这类不涉及凭据的操作可以交给 AI 动作步。别把登录放进 `Background`——它对每条 scenario 各重复执行一遍，不是复用登录态的办法。见[编写 .feature](./writing-features.md#三个有语义的-tag)。

### 测试账号的密码写进 `.feature` 安全吗？

不安全，别写：step 文本会原样交给模型，还会留在判定明细、失败原因与报告里，密码这类值应由确定性 step 从环境变量读，用例只用在测试环境有效的凭据，见[编写 .feature 的「敏感信息」](./writing-features.md#敏感信息)。

### 几十条用例运行一轮大概多久？能同时执行几条？

默认串行，总时长约等于各 job 时长之和；调高并发后才由并发度与最慢的那个 job 决定。同一个 `@scope` 里的 scenario 串行共享一个会话，只有不同 scope 之间能并发，并发上限要在命令行上显式调高；用 `submit` 提交到云端后端时还受部署侧设定的上限钳制。单个 job 另有墙钟预算，到点即被停掉并判出错。见[运行测试与查看结果](./running-and-results.md)。

### 同一批用例在本机和在云端运行，结果会一样吗？

引擎与判定逻辑是同一套，差别在配置从哪来：本机 worker 继承你 shell 里的环境变量、读本机的 `steps/` 目录；云端 worker 不继承你 shell 里的变量，确定性 step 与配置要构建进镜像，少数变量由起这个任务的那一方注入、压过镜像里的同名项（哪些变量、在哪里设见[配置](./configuration.md#配置生效的四个位置)）。所以两边的模型或 step 不一致时，同一条用例可能给出不同结论——改完确定性 step 要重新构建并推送镜像，云端才跟上。见[编写确定性 step](./writing-deterministic-steps.md#带到云端)。

### 一个 AWS 账号里能同时运行 stage 和 prod 两套后端吗？

能。用不同的 `--prefix` 各部署一套，表、桶、集群与参数都按前缀分开，提交时给同一个前缀就落到对应那一套。两套各自记版本、各自维护 worker 镜像，升级与拆除都要分别做一遍。见[部署与维护云端后端](./cloud-backend.md#后端包含什么)。

### 结果能输出成 CI 面板读得懂的报告吗（例如 JUnit XML）？

没有 JUnit XML 或其它第三方报告格式的输出。CI 里的接法是退出码加 `--json`：退出码表判定，`--json` 给机读结构；此外还有可点开的 HTML 入口与机读的产物清单：本机运行时落在报告目录、可整目录当构建产物存档，云端后端下落在产物桶的同构目录。见[运行测试与查看结果](./running-and-results.md#机读输出)。
