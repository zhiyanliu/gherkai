# 通用 step 能力清单：抽象原语 + 两个引擎对称映射 + 边界发现

> **Status:** Accepted

v0.x 验证「QA 只写 `.feature`、零 step 代码」靠一组**通用 step**（任何用例复用，QA 不写代码）。本 ADR 固化打磨出的能力清单、两个引擎对称映射、刁钻用例暴露的边界。generic step 是产品核心——**它的能力边界 = 产品能力边界**。

## 通用 step 应是「抽象原语」，不是绑场景的句子

打磨中为了快速验证，临时写了像「页面上展示的语言版本数量应该大于 N」「词条首段应该提到 X」这种**绑死维基场景**的 step——它们能跑通，但**不是真正的通用 step**（真实项目不会有"语言版本数量"这种 step）。真正的通用 step 应是**抽象原语**，QA 把场景细节放进引号里的自然语言，而非放进 step 措辞。

> **已收敛（v1.0）**：绑场景临时句子已全部归纳成抽象原语——现 `features/*.feature` 里只剩 `When/Then "{自然语言}"`（默认 AI）+ `Given 打开 "URL"`（导航）+ `Then 页面地址匹配 "正则"`（确定性锚点），无任何绑死场景的 step。其中**取数/取串两条原语后被删**（避免过度设计——QA 直接写自然语言让 AI 判，需精确数值走确定性锚点，见 CONTEXT 与下「待深化」）。

**原语清单（含已删项，留作设计史）**：

| 原语 | 语义 | Midscene | Nova Act |
|---|---|---|---|
| 导航 | 打开 URL | `page.goto` | `go_to_url` |
| AI 动作 | 执行自然语言指令 | `aiAct` | `act` |
| AI 布尔断言 | 问是非（+投票） | `aiBoolean` | `act_get(BOOL_SCHEMA)` |
| AI 取数断言 | 提取数字再比较 | `aiNumber` | `act_get({type:integer})` |
| AI 取串断言 | 提取文本再判断 | `aiString` | `act_get(STRING_SCHEMA)` |
| AI 否定断言 | 确认"不存在"（问肯定取反+投票） | `aiBoolean` 取反 | `act_get(BOOL_SCHEMA)` 取反 |
| 确定性锚点 | 不靠 AI 的精确检查（URL/DOM） | `page.url()` 等 | `nova.page.url` 等 |

**两个引擎对称（精确化）**：提取类从「对称布尔路径」推广到「对称提取路径」——`aiNumber/aiString` ↔ `act_get(各 schema)`。**但对称仅在命题清晰时成立**；命题措辞有歧义时两个引擎表现可能分叉（见下"负向验证"：同一句宽松断言 Midscene 判 false、Nova Act 判 true）。是 [0010](./0010-spike-as-apples-to-apples-benchmark.md) 对称论断的扩展 + 边界修正。

## 刁钻用例暴露的边界（两批打磨）

**第一批 · 断言类（① 提取数据 + ⑤ 否定断言）—— 两个引擎对称通过**：
- 提取数字/字符串再做确定性比较：可行（上表）。
- 否定/不存在断言：用「问肯定句再取反 + 投票」策略，两个引擎都过。

**负向验证（"该红能红"，2026-06 实测，两个引擎各一探针）**：
- **Midscene**：4/4 正确——必假命题（说成 Python/数 >9999/含杜撰词）全判 false，对照正向判 true。`aiNumber` 还真取到页面真实值（92 种语言）。AI 断言有判别力，非"无脑绿"。
- **Nova Act**：起初一个必假命题（"当前页面是关于 Python 的维基词条"）判成 **true**（误）。**追查后定性反转**（避免冤枉引擎）：
  - 诊断实验（隔离感知/判断/歧义）显示：① 它**感知正确**（明确知道主题是 OpenAI）；② **无正向偏置**（无关命题 猫/足球/巴黎 全判 false）；③ 把命题措辞从"是关于 Python 的吗"改成"**主题**是关于 Python 的吗"后，即正确判 false。
  - **真因 = 断言措辞歧义 × 页面内容重叠**：OpenAI 词条本就大量提到 Python，"是关于 X 的吗"这种宽松问法，模型看到满屏 X 内容就可能判 true。不是引擎缺陷、不是 API 语义问题、不是正向偏置。
- **纠正的过激结论**（存档防再犯）：曾据这一个误判跳到"Nova Act 正向偏置 / 推翻对称论断 / 正向用例是假象"——**全部收回**。两个引擎断言都有判别力。教训：先证伪最朴素解释（措辞歧义/看岔/单点偶然），再上升到系统结论。

**第二批 · 鲁棒性（② 多步骤 + ④ 模糊判定）**：
- ④ 模糊/主观判定（"内容详实、结构完整的百科条目"）：AI 投票**两次都稳过**，主观断言在此例未暴露抖动。
- ② `aiAct`/`act` **一次能吃多步**（"搜索+打开+点击"三步执行层 OK）。
- 🔴 **关键边界**：多步骤里含**开放性动作**（如"点正文里第一个带链接的词"，结果不可预测）→ 页面进入不稳定瞬态 → **后续断言间歇性 flaky**（首跑挂在 `page.screenshot: Target page has been closed`，复跑过）。多步可控动作（搜索+打开特定页）则稳定。

## 实践约束（据边界发现）

- 多步动作应**目标明确**（导航到特定页），**避免开放探索式动作**（点任意链接）；后者会引入页面瞬态 flaky。
- 这印证 [0014](./0014-ai-first-assertions.md) 抖动治理不止于断言：**动作的页面瞬态也是 flaky 源**，断言前可能需"等页面稳定/重试"。
- 与 [0015](./0015-v1-positioning-smoke-not-regression.md) 的「柔性 vs 可控」张力一致：开放动作=高柔性=低可控。

## 已知风险：AI 断言对措辞歧义敏感（不是已解决的问题）

- 断言句的措辞精度显著影响判定（"是关于 X 的吗" vs "**主题**是关于 X 的吗"可翻转结果），且两个引擎敏感度不同。
- **这是已知风险，不是已找到的解法**。原因：
  - 数据点太少（措辞翻转只观察到 1 例，未重复多次，无法排除偶然）。
  - 即便"严格主旨措辞"有效，**要求 QA 写严格措辞本身违背"QA 随便写自然语言"的产品前提**；框架自动改写 QA 断言又等于猜意图、有风险。
- 故**不把"措辞规范"当作提升某个引擎可靠性的承诺**。它是 v0.x 记录在案的可靠性边界，留待更多用例数据评估（也可能最终靠"确定性锚点兜底关键断言"而非靠措辞，见 [0015](./0015-v1-positioning-smoke-not-regression.md)）。

## 待深化（不阻塞）

- 否定断言「直接问否定句 vs 问肯定取反」对比。
- 多步+开放动作的 flaky：断言前加稳定性等待/重试，验证能否消除。
- 措辞敏感度：多用例多次重复，量化它对两个引擎可靠性的真实影响（现仅 1 例）。
