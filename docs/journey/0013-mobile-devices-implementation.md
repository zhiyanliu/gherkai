    3. job 级终态只写一次、报告由已提交的记录生成（六步做完之后单独设计）。现在 run 级终态是条件写、只有一方写成，报告也只由收尾写成的一方生成；job 的退出记录却可以被再写一次覆盖（接力方补写的未知退出之后被真实退出码覆盖），判定明细由各推进方各写各的。目标：退出记录先到先得、之后不变；报告只从已提交的记录生成、任何一方都能重建。「报告只由写成的一方生成」与它留下的两个窗口（写成的一方中断时没有报告；判定明细可能被没写成的一方覆盖）随之消失。已知代价：晚到的真实退出码被放弃（那时这个 job 已过截止时刻，记超时成立）；要把「算到哪一条事件为止」记进提交的记录。动的是 ADR 0034 的机制，走完整的设计复核。随这一项一并校准两处现在并不成立的旧说法：「报告可从 RunResult 重建」（前台收尾的注释与 ADR 0030，实际没有重建的入口）、「判定真值可由 events 重放重建」（ADR 0034 三件套表，事件过了保留期之后重放会得出错的结果）。云端流过滤的理由（部署包的注释、测试与 DEVELOPMENT）已在第 5 步里改成只陈述所在 code 做的事、指向 ADR 0034「已收尾的 run 不再推演」条；ADR 0033「events 表开 TTL」条里「三条护栏须同时成立」的第②条现在只挡不带新信息的触发（推进步骤自己读到终态即返回），这句要求要不要改写随第 6 步改流过滤时定。
    4. 方法文档 `docs/ai-eng/peer-review.md` 的修改（并发类结论的间隔核查、基准里的性质带前提、熔断的触发与恢复条件、发送工具区分首轮与后续轮）：owner 已批准（2026-11-15，拟议文字经另一家模型六轮评议闭合）。方法文档、发送工具与测试、ADR 0046 决策 6、词表的 owner 词条与 ADR 0040、CLAUDE.md 两处（独立复核一条、「代码纪律」新增「执行方式不改变判定」）、CONTRIBUTING、`.claude/README.md` 都已改在工作区并过本家独立复核，已单独提交（另一家模型落地复核四轮闭合）。发送工具现在是新形态，每一轮都要带 `--round first` 或 `--round followup`。还差一件：CLAUDE.md 引入 `.claude/README.md` 的那一行是否生效，要在下一个会话开头核对上下文里有没有它的内容；没有的话改用 `.claude/rules/` 下不带路径限定的文件（ADR 0046 决策 7 随之改）。
