## owner 定的写回口径

- 这次重新设计是对之前设计的修正。不新增 ADR，不把内容堆进一篇：每一项决定写在「做这件事的人会去读的那一篇」里，别处放指针。
- 旧设计删掉、当作没有发生过；只把讨论中权衡过的做法留作被拒方案，理由写设计上的依据。ADR 里不提升级、迁移与版本共存。
- 读起来不能有打补丁的感觉：能原位改写既有小节的不新增小节；标题、背景、决策的开头句直接陈述现在的设计，不写「后来发现」「不再」「改为」。
- 文件名与改写后的内容对不上就改名，引用同步更新、保持有效。
- 用词：统一用词表的规范名「推进器」；run 级叫「run 处置」，job 级叫「job 到点停止」；「执行方式与执行后端有三种组合，云端后端只有后台」。
- 描述行为的文档（internals、用户指南、agent skill、机读契约页、CHANGELOG）随各实装批次在同一笔提交里改，这次只改 ADR 与词表。
- 进度记在本文。ADR 的 Status 头只留一句状态（这一篇描述的设计有一部分尚未实装），不列清单、不指向 journey；下面各篇「Status 头」一栏里列出的「尚未实装」清单记在本文「实装」一节，不写进 ADR。

## 0054 的范围、标题与文件名

【管什么】改写后 0054 只管「一个 run 的生命期」，四块：①运行期限（决策二），以及让每个 run 都有期限的前提：每个 job 的墙钟预算有产品上限（决策十）；②生命期锁及其前提：本机 run 的推进进程对 run 目录持锁，死活靠试拿锁回答（决策三）；锁只在本机文件系统上的报告目录里有效，由边界检查保证（决策四）；③终态不可变、执行方服从记录：run 到终态之后运行态的任何写都不成立，执行方每次启动之前以 run 未结束为条件认领，所以期限之后结束一个可能还在执行的 run 也安全（决策五）；④run 处置：死活的判断与可以处置的条件（决策六），处置做什么（决策七），处置方与入口（决策八），云端后端到期结束 run 并清扫 task（决策九）。
【不管什么，各归哪篇】本机 run 至多一个推进器、云端重叠推进、各命令写什么、重叠时各记录的先后、写入序号：0034（「推进器与触发源」「命令形态」机制三）。run 与 job 的状态怎样取、结束写给未结束的 job 记什么、说明表：0031 决定三（结束写是其中的小节「结束写：结束一个未结束的 run」）。明细的写序、点名、状态的权威：0030 决定三。报告由谁、从什么生成：0027。云端后端只支持 submit：0016 决策 A。退出码：0031 决定五。list-runs 的列与提示：0041 决策七。doctor 的报告目录一项：0041 决策四。被期限截断记 aborted 的状态语义：0031 决定一；截止时刻怎么算仍在本篇决策二第 2 条。

## 词表

按 ADR 0045 决策八的次序：先改 CONTEXT.md，再写各篇 ADR（词表与 ADR 在同一提交落地，见 order）。词条须是规范名加一两句「是什么」，_Avoid_ 只列词，句末至多一个 ADR 指针。

一、新立四条，都放「执行与推进」节：
- 生命期锁 (run lifetime lock)：本机后端执行一个 run 的进程对它的 run 目录持有的排他文件锁，持有到管这个 run 的进程退出（提交时经一次交接转给后台推进进程）；别的一方拿得到这把锁，就说明管这个 run 的进程已经不在（见 ADR 0054）。_Avoid_: 发起进程标识、进程核对
- run 处置 (run settling)：管一个 run 的进程已经不在、或已过运行期限加 300 秒时，由别的一方以结束写把这个 run 结束（见 ADR 0054）。_Avoid_: 遗留 run 收尾
- 结束写 (ending write)：结束一个未结束的 run 的唯一写法：一次写把每个未结束的 job 写成终态并各带一句说明，run 随之成为终态（见 ADR 0031）。_Avoid_: 到期收尾、收尾写
- job 到点停止 (job cutoff stop)：执行中的 job 到了起作用的截止时刻（它自己的墙钟预算或 run 的期限）被推进器停下；被期限截断的不算超时（见 ADR 0034）。_Avoid_: 超时处置、到点处置
「点名」不单独立条，写进「判定真值」。
