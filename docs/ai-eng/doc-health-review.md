# 文档健康度复盘（全部项目文档）— 任务说明

> 给执行此任务的 AI agent：本文件是**可复用的任务指令**。读它就按这里的目标与方法做，不要退化成「扫一眼改改错别字」。标 **【强制】** 的步骤不可跳过——它们是这套复盘产生价值（而非走过场）的关键，省掉任何一个都会漏掉真问题或误改。姊妹任务见 [`code-health-review.md`](./code-health-review.md)（代码复盘）。文末「已知失败形态」是各条规则的来历，规则本身不复述它。

## 为什么做（价值）

ADR / CONTEXT 是随构建**逐步长起来**的：每次在前人文档上叠加、修改，单点看合理，累积起来会漂移——描述与 code 脱节、跨文档自相矛盾、同一事实多处重述且各自漂移、坏链接、被取代的决策没标历史。这些债对**读者是 contributor 侧 AI agent（约 80%）**的文档库尤其致命：AI 据陈旧或矛盾的文档去构建，会把错误放大进 code。此任务定期把文档拉回「高密度、单一事实源、精确、无矛盾」的状态。

## 何时做（触发）

**事件驱动，非纯周期**：文档漂移是构建的函数、不是时间的函数。触发时机——完成一个显著构建里程碑后 / 一批 ADR 有增改后 / 主观感到文档跟不上 code 时。没构建就别空跑。

## 目标与准绳

- **读者比例决定优化方向**：ADR / CONTEXT 约 80% 给 contributor 侧 AI agent 读 → 优化向**信息密度、单一事实源、精确指针**，冗余 = context 噪声、敢压；README 约 80% 给人读 → 保叙事、不激进压缩。**据此定每一处「压缩 vs 保留」。**
- **单一事实源**：同一事实应有唯一权威表述，别处用**带指针的简短重述**引它——不是各写一份完整副本（那必漂移）。
- **精确无歧义**：与 code 不符即错；坏链接即错；行号引用易漂移（尽量用「XX 段」而非「line N」）。

## 红线护栏（违反 = 改错了）

- **绝不删**：决策理由（why）、权衡（trade-off）、反模式 / 被拒方案、关键不变量。压缩时必须完整保留——这些是 ADR 的核心价值。
- **有意重复 ≠ 冗余**：ADR 该能被（AI）单独读懂，跨切面事实带指针的**简短**重述是可读性设计。只压「同一事实多处**完整**重复且已漂移」的。
- **历史记录 ≠ 过时**：明确用「曾 / 原 / 已被 X 取代」框住的旧世界是有意保留的决策脉络，不算过时、不删。
- 不改 ADR 编号、不跨 ADR 搬内容（除非专门决策拆分）。

## 六类问题（分类找）

1. **CONTRADICTION**：文档内部自相矛盾，或两文档互相矛盾。
2. **STALE**：描述与当前 code 不符，或描述已被取代的旧世界却没标历史。
   - **「对照 code」是检测手段、不是权威**（本项目先 ADR / CONTEXT 后 coding，设计文档不瞄着 code 写）。发现不一致后按三类处置，**判据 = 被引句是「对实装的描述」还是「决策 / 契约 / 不变量」**：
     - ① **描述性内容**（路径 / 文件名 / 模块 / flag / 依赖版本 / 实装现状注 / 实测证据）→ **随 code 校准文档**（ADR 不是它们的权威）。
     - ② **被后来的 ADR 有意反转的决策** → **给旧 ADR 加 Status 反向链与历史注、不改决策本身**（权威仍是新的那篇 ADR）。
     - ③ **code 偏离了 ADR 已定的设计、且没有任何 ADR 记录这次偏离** → **不落文档改、不算客观类**：报人裁定是「实现没对齐设计 → 改 code」还是「设计该变 → 人拍板后显式改 ADR」，并移交姊妹任务 [`code-health-review.md`](./code-health-review.md) 的 VIOLATES_ADR 条接收。**报裁定时必附复盘方的倾向**（实现更合理还是设计更合理）**与理由**（两边各能核到的真值、代价、与其它 ADR 的牵连）——人只做拍板、不从零判；只报「不一致」不给倾向 = 未完成，把判断成本原样推回给人。
   - **本任务最该防的误伤**：复盘顺手把 ADR 改成 code 的样子 = 把漂移合法化。
3. **DEADLINK**：指向不存在的 ADR / 文件 / 锚点，或引用已删除的字段 / 函数名。对 REFERENCES.md 与技术笔记这类「外部来源 + 源码内点」文档额外查：① 文中指向的源码路径 / 内部符号是否随重构失效——对照 code 核实；② 外部 URL 是否明显过期（不强求逐个 fetch，但结构性失效 / 改版要标）。
   - **引用方向违规**（悬空指针的一类，判据见 CLAUDE.md 文档纪律「悬空指针红线」条）：长期文档里指向 `docs/journey/` 的链接、裸 WP 编号、只在某次会话成立的指代（「#1 修复」「本轮那个 bug」）一律报。**修法不是删信息**：把被引的证据 / 结论**内联**进 ADR 使其自包含，血缘用**对未来读者自明的事件描述**替代。Draft ADR 可暂留 journey 引用、Accepted 必清——这条例外绑死 Status 头，审计点见下「Status 头」节。
4. **REDUNDANCY**：同一事实多处完整重述且漂移 / 可合并段落 / 可精化冗长句 / 单 ADR 内可重组以提升 AI 检索的段落顺序。
5. **SEDIMENT（施工叙事沉积）**：迭代过程叙事在长期文档里的残留——「先做 X 后发现 Y 改成 Z」的施工节奏、「P3b / 步骤几」这类过程编号、被后续迭代覆盖却没删的旧描述层、**现场流水**（坐标型数字——run_id / revision 号 / 时刻 / 单次耗时——与逐条命令过程；判据型数字不算，粒度判据见 CLAUDE.md 文档纪律「内联粒度判据」条）。**处置：归主观类待批**。
   - **检测**：它是构建的累积函数，快照式读当前文照不出——检测法见第一层【强制】提纯审计。
   - **留 / 删边界**：留「为何这样设计」（why / 被拒方案 / 决策脉络），删「分几步 / 施工节奏 / 过程编号」——判据即 CLAUDE.md 文档纪律首条给 ADR 划的内容边界，写入与审计同一把尺。
   - **不误伤**：把某次实测 / commit 当稳定证据内联引用的是自包含证据、不是沉积；`docs/journey/` 里过程坐标合法。过程编号作为叙事归本类，作为指向 journey 的悬空引用归 DEADLINK——同一句可能两症并发，按各自修法处理。
6. **TONE（口吻 / 可读性 / 术语，对全部人读文档；判据 = ADR 0045 决策六与决策八）**：
   - **使用者向文档**（`docs/user-guide/**`、根 README、各包 README、`CHANGELOG.md`、Release 正文 footer、agent skill）：产品说明口吻之外的写法都报——隐喻与俏皮话、同事口头语、施工叙事（「我们这次 / 本轮」）、无动词的标签句、面向同事而非使用者的措辞、术语未定义就用、晦涩内部术语。**处置：主观类待批**，报法 = 引原句 + 给改写句。
   - **技术文档**（CONTRIBUTING / 各包 DEVELOPMENT / `.github/workflows/README.md` / internals / `tools/*.md`）：报俏皮话与口头语，不报密度（允许术语）。
   - **术语面**：人读文档（含 internals 与图源）里出现 CONTEXT.md `_Avoid_` 登记的旧名或非规范名即报。**分流判据**：先查该词在护栏属哪张表——`COLLOQUIAL` 只约束人读层与产品文案、`RETIRED_TERMS` 管用词版本；`_Avoid_` 登记的是完整术语名时不推及其前缀或子串；同一退役名跨多篇时**必须一次做完并附全量落点**。发现规范术语本身不合书面标准时**不就地改文档**，报为「词表项」交 owner，改名走 ADR 0045 决策八的顺序（先词表、再传播）。
   - **护栏分工**：正则能抓的（禁词、退役旧名、口头语表）已由 `cli/tests/test_user_docs.py` / `test_package_readmes.py` / `test_skill.py` 机械挡住用户文档、图源、skill、包 README 四面；本类抓正则外的语义与可读性，并补技术文档与 internals 那半的术语面。contributor 侧 AI agent 文档不在本类射程。

## 按文档类型的复盘侧重（用对判据）

不同类型的文档，主要风险不同、别用一把尺子：

- **ADR**：决策一致性、跨文档矛盾、被取代未标历史、Status 头（见下）、SEDIMENT（ADR 是其主战场）、引用方向合规 + Accepted 自包含。
- **CONTEXT.md**（严格词表，ADR 0045 决策八）：每条是否仍是「术语 + 一两句定义 + `_Avoid_` 只列词」；定义有无实现细节或过时；`_Avoid_` 是否漏登已退役旧名、或误登了仍在合法使用的另义词；术语本身是否合书面标准（判据与修法见上 TONE 术语面条）。提纯判据在这里**反向**：why / trade-off / 反模式出现在词条里不是「保留」而是「搬回 ADR」。
- **用户文档**（`docs/user-guide/**`、根 README、各包 README、`CHANGELOG.md`、`.github/release_body_footer.md`）：安装 / 命令 / 参数 / 退出码 / 环境变量 / 模型名逐项对 argparse 与 code 做差集；保叙事。**加查三样**（判据 = ADR 0045 决策一 / 三 / 六，ADR 0039 面一，CLAUDE.md 文档纪律「文档按读者三分类归位」）：① **使用者向边界**——contributor 内容（目录结构、开发环境、测试、spike、发布流程）或内部指代（ADR 编号、决策号、内部机制名）出现在使用者面 = 越界，修法是搬去 CONTRIBUTING / 同目录 DEVELOPMENT、不是删；用户文档不把读者链到 ADR / CONTEXT / CLAUDE.md / journey / ai-eng；② **owner 表与入口页形态**——`docs/user-guide/README.md` 是 owner 表，同一主题在两页各展开一遍 = 双源，修法 = 定归属、其余压成一句 + 链接；各包 README 只许四样（一句定位 / 装法 / 最小用法 / 绝对 URL 指向 user guide），多出的叙事 = 越界、搬回 user guide；③ **口吻**（TONE 类）。护栏 `cli/tests/test_package_readmes.py`（包 README + Release footer：禁词、相对链接、钉 tag）、`cli/tests/test_user_docs.py`（user-guide / 根 README / CHANGELOG：禁词、相对链接可达、不链 contributor 侧文档、owner 表两向差集、默认模型 id 与引擎常量一致）、`cli/tests/test_release_notes.py`（每个已发行 tag 在 CHANGELOG 有节）只管正则与真值集，正则外的语义越界靠本任务。
- **contributor 文档**（根 `CONTRIBUTING.md` + 各包 `DEVELOPMENT.md`，`.github/workflows/README.md` 同侧）：目录树 / 测试与开发命令 / 护栏清单 / ADR 编号范围与指针——全是枚举型，逐条对 `ls` / `git ls-files` / argparse；允许 ADR 指针与内部机制名，不允许俏皮话。
- **其余 README / 目录索引页**（`core/tests`、`skills`、`docs`、`docs/ai-eng`、`docs/internals`）：不进发行包、按 contributor 向 / 索引页判，**ADR 指针与相对链接在它们里合法**；`skills/README.md` 只是指路——源文件在 `cli/`，本目录只有评测资产。
- **docs/internals/**（给人的阅读理解层，派生视图）：按 README 同侧判据（保叙事）；主查 STALE（对照 code 与权威 ADR）、**越界复述 why**（决策理由出现在正文 = 双源苗头，修法 = 压回指针；写作判据在 CLAUDE.md 文档纪律 internals 条）、**篇间归属与重叠**（同一机制只一篇作 owner、其余给指针；修法 = 定归属 + 留指针，不是压句子；新增 internals 篇时既有篇的延伸阅读要指过来；归属表 = `docs/internals/README.md` 索引）。**图源 `docs/diagrams/*.json` 同属派生视图**：节点 / 边 / 顺序对照 code 与正文，图上出现会漂的字面量或与正文双写规则报 REDUNDANCY；改动后跑 `tools/build_diagrams.mjs` 重出 SVG，JSON 与 SVG 同 commit（ADR 0045 决策七）。`cli-json-contract.md` 的字段清单已由 `cli/tests/test_cli_json_contract.py` 与 `deploy_aws/tests/test_workers.py` 对真渲染器逐键断言，本任务只查字段**释义**与出现条件，不手工对字段表。
- **agent skill**（`cli/gherkai_cli/skills/gherkai/**`，随 CLI wheel 发行）：按各包 README 同侧判据（零内部指代、只用绝对 URL、跨文件指针写反引号裸路径），去向见 ADR 0039 面二 + [0043](../adr/0043-agent-skill-for-driving-gherkai.md)。护栏 `cli/tests/test_skill.py`（禁词 / 相对链接 / URL 钉 HEAD·tag / flag 归属 / JSON 键名 / 契约副本等值）与 `deploy_aws/tests/test_skill_deploy_tokens.py`；本任务只查语义越界与「安装态的 agent 照它做还对不对」。**`references/cli-json-contract.md` 是 `docs/internals/cli-json-contract.md` 的确定性转换产物、一律不手改**（改源页后跑 `tools/render_skill_contract.py`），本任务查的是那份手写源与 code 是否一致。
- **REFERENCES / 技术笔记 / 配方 / 工具手册**（`docs/ai-eng/REFERENCES.md`、`engines/midscene/spikes/SIGV4-FETCH-RECIPE.md`、`tools/e2e_harness.md` 这类）：没有「决策矛盾」维度，重在「配方 / 引用还灵不灵」——代码片段是否还与当前 SDK / 实现对得上、踩坑点是否还成立、指向的源码路径 / 外链是否有效。
- **方法文档与入口**（`docs/ai-eng/{doc,code}-health-review.md`、`diagram-authoring.md`、`.claude/commands/*.md`、`.claude/skills/doc-diagram/SKILL.md`）：只查 DEADLINK / STALE / 内部矛盾 / SEDIMENT，入口是否仍只含指令与指针、没长出要点复制（入口不复述方法，免同步漂移）；**规则内容本身是决策、不在复盘里改**（改规则的唯一入口见「产出与提交」的方法复盘），SEDIMENT 只动措辞不动规则（亲历数字、轮次坐标、同一规则的第二遍重述），按主观类出提案待批；不进提纯审计集的 git 层读。
- **CLAUDE.md**：只查 DEADLINK / STALE（点名的护栏测试文件、ADR 编号、目录名、节名是否仍存在、与所指 ADR 是否一致）；规则内容不在复盘里改。
- **`docs/journey/`**（staging 区，可为空）：只做生命周期审计——非空时逐个判「该吸收进 ADR / code 后删」还是「任务仍在推进、留」，不做密度 / 提纯（判据在 CLAUDE.md 文档纪律 journey 条）。
- **评测资产**（`skills/gherkai-evals/grader-prompt.md`、`evals.json`、`trigger-eval.json`）：只查 STALE——点名的 CLI 命令 / 字段 / 退出码 / 输出文案是否仍对得上真值；模拟用户口语的 prompt 不算口语问题（资产清单见 ADR 0043 决策七）。

## 执行方法（多轮复盘验证过的最佳路径）

**一轮的次序**：⓪ 按锚点读上轮落地提交里的「方法复盘」，其提议的规则变更作为本轮第一份待批 → ① 定覆盖范围 → ② 第一层片内审计（含全部【强制】项）→ ③ 第二层 cross-ADR（【强制】）→ ④ 第三层事实族横切（【强制】）→ ⑤ 落地（见「落地纪律」）→ ⑥ 提交（见「产出与提交」）。**三层是一轮里的三个视角、不是三轮**：第三层按事实族切、与前两层按文档切正交，同一轮里都要做。

**覆盖范围 = 全部项目文档**，凡人 / AI 会消费的项目 Markdown 与登记在册的 JSON（图源、评测资产）都在内，判据按上「按文档类型的复盘侧重」取：`docs/adr/*.md`（重点）· `CONTEXT.md` · `docs/ai-eng/REFERENCES.md` · 用户文档（`docs/user-guide/*.md` 含 owner 表 `README.md`、根 `README.md`、`CHANGELOG.md`、`.github/release_body_footer.md`、各包 README——入口页、逐字上 PyPI / npm，包清单靠 `ls` 现列、不在此硬编码）· 其余 README（`core/tests`、`.github/workflows`、`skills`、`docs`、`docs/internals`、`docs/ai-eng`；`docs/README.md`、`docs/internals/README.md`、`docs/ai-eng/README.md` 三份索引兼 owner 表，与目录内容两向差集）· 评测资产文档 · 全部 contributor 文档（根 `CONTRIBUTING.md` + 各包 `DEVELOPMENT.md`）· `CLAUDE.md` · `docs/journey/` · 方法文档与入口 · `docs/internals/*.md` · `docs/diagrams/*.json` · 随 CLI wheel 发行的 agent skill markdown（`SKILL.md` + `references/*.md`）· 技术笔记 / 配方 / 工具手册。未来新增的 docs/ 与子工程根下文档同样纳入——每次 `find . -name "*.md"` 扫一遍、别漏新文件，排除项见下（唯一权威清单）。

**明确排除**：`.claude/` 里未入库的个人项与 `.agents/`（入库的 `.claude/commands/`、`.claude/skills/doc-diagram/SKILL.md` 在范围内；入库的 `.claude/settings.json` 与 `.claude/hooks/` 不是 markdown、不在射程）；`node_modules/`、`.venv/`、`.pytest_cache/`；`graphify-out/`（graphify 生成物，刷新走 CONTRIBUTING.md「知识图刷新」）；repo 内 code 注释 / docstring 的引用方向违规归姊妹任务 `code-health-review.md`（本任务管 `.md` 与登记在册的 JSON——`docs/diagrams/*.json` 图源、`skills/gherkai-evals/*.json` 评测资产，分工线两侧一致）。

### 第一层：片内审计（可用 workflow 并行）

- **分片按主题耦合分组**：把主题相关、易互相矛盾的 ADR 分在同一片，便于发现跨片矛盾。聚类真值 = ADR 互引图（第二层那张，先算）+ 各 ADR 点名的 code 文件重叠；不照抄某一时刻的固定分组，知识图社区不作依据。
- **【强制】STALE 类必须 Read / Grep 实际 code 核实**，禁止凭印象。
  - **枚举型内容是最高收益的机械核对点：做「文档清单 vs 真值集」的差集、别靠读**——目录树 / flag·选项表 / 模块清单 / 字段·事件类型列表 / 交叉引用 / ADR 编号范围，每一项拿文档清单去 `ls` / grep / argparse 逐条比对源真值。遗漏项在读「已列出的内容」时是隐形的，读列表本身永远发现不了漏了什么。
  - **真值集构造命令自身要自检条数**（`wc -l` 与 `grep -c` 对账）；CJK 词表做差集必须 `LC_ALL=C`、别用 `tr` 切多字节分隔符——假真值集比不做差集更危险，它看着做了。
- **【强制】矛盾 / 过时 / 坏链接等客观类，逐条对抗验证**：交一个独立视角读原文 + code 尝试**证伪**（默认怀疑），只保留 CONFIRMED 的——防把有意历史记录 / 风格偏好当成 bug。
- **【强制】提纯 / 密度审计**——纠错抓「错」，这条抓「稀」；没有它，复盘会结构性偏向纠错、提纯永远被挤掉。
  - **审计集 = 全部 ADR + CONTEXT**（CONTEXT 的判据反向，见上侧重节）。**有界工作量靠跨轮沿用、不靠缩范围**：自上轮以来无改动的 ADR 可沿用上轮对它的具名结论（仍是内容锚定、可核）；动过的必须重审。**退场条**：同一篇连续三轮沿用即须补一条本篇自身的内容锚（点名受保护要素 + 定位），不许纯引用链。**锚点 = 上轮落地提交**，定位靠 trailer 不靠自然语言（两个 trailer 的写法与哪个提交算落地提交见「产出与提交」），四步：
    - ① 取锚点：`git log --format='%h %(trailers:key=Doc-Health-Round,valueonly)' | awk 'NF>1{print; exit}'`（**别用 `grep -m1 .`**——无 trailer 的提交也输出非空行、它恒命中 HEAD，后果见文末；trailer 缺失的早期轮次退回 `git log --grep=提纯`）。
    - ② 取回上轮具名记录：`git show <锚点>^:<路径>`（路径见锚点的 `Doc-Health-Records:` trailer）——记录随落地一起删、git 历史就是它的归宿。
    - ③ 判动没动：`git log <锚点>^..HEAD -- <路径>`（起点用锚点的**父提交**，否则上轮刚改过的文档会被误判成「未动」）；零命中 = 可沿用、有命中 = 必重审；**动 / 没动清单写进报告**。
    - ④ 排序（churn 只决定读的细致程度，**不做截断线**）：热区 = 动过的文档 ∪ 一跳依赖（引用了动过的 ADR 的其它文档，引用图入度）先读。首次执行无前轮可沿用 = 全量深清、建立基线。
  - **检测（时间维度，与 STALE 同构）**：提纯的真值集是**文档自己的 git 历史**——对审计集逐个层读增长史，找「被后续迭代覆盖却没删的旧描述层」与「逐层叠加的施工括注」。**层读三步、必须有界**：`git log --oneline` 看层数 → `--stat` 挑大改层 → `git show <commit> -- <file>` 只读大改层的差异（**别对长历史文件全量 `git log -p`**，会撑爆执行者上下文）。
  - **判据（密度非行数，逐句布尔、无任何百分比 / 行数触发线）**：逐句问「这句是否承载受保护要素」——要素以「红线护栏」节为唯一源，增补四项：决策本身、精确指针、Accepted ADR 内联的自包含证据（判据型；坐标型现场不在保护内）、叙事连贯骨架句。不承载任一 = 填充 / 施工流水 / 可指针化的完整重复 = 提纯候选。**密度与行数解耦**：250 行逐句全承载 = 满密度不动；短段落半数过场 = 照报。**粒度在候选句自身跨度上评**，保护不从邻居继承。**骨架句限定**：受保护的是让论证可跟随的结构功能（过渡 / 框定 / 次序），不是挂在骨架上的重述——测试 = 删了它论证结构是否断，仅重述已说过的点则骨架去掉它照样立；在 ADR 上援引「骨架」须说清丢的是哪个结构功能，不能只说「读着顺」。
  - **提案过独立红线复核**：每条提纯提案交独立视角对照红线护栏尝试**证伪**（宁严勿松，拿不准即否决）——与客观类的对抗验证同构，真值集换成红线护栏。已知误伤形态见文末。被否的存档不落改。
  - **产出槽（本条的牙）**：报告**必须**含具名提纯审计记录——审计集里每篇一条：提纯提案，或判无 + 一句依据。**判无依据须内容锚定、不可移植**——点出具体险成候选却因某要素（指名 + 定位）留下的句子，或复述 git 层读到的史实；一句原样可粘到别的 ADR 还成立的套话不算数（人可抽查任一条判无依据对 `git log -p` 复核，依据可移植 / 不可核 = 该步判失败）。**空槽 / 沉默 = 该步未执行、复盘未完成。**
  - **无配额**：不设「必须报 N 条」——配额会把执行者逼向最长的散文（恰是 why / trade-off / 内联证据）下刀凑数。真干净就零候选，牙在「必须审、必须具名交代」。

### 第二层：cross-ADR 视角（【强制】，片内审计漏掉的结构问题）

- **构建引用图**（谁引用谁、入度 / 出度）：找孤儿节点（无人引用，可能已废）、超级枢纽（出入度都极高——高内聚总纲不该拆，只在「某段频繁独立变更且牵动无关段」时才是拆分信号）。**顺带标记反向违规边**：任何「长期文档 → `docs/journey/`」的边都是方向违规（稳定物依赖了易删物），引用图里一眼可见——全部报（修法见 DEADLINK 引用方向违规条）。
- **Status 头一致性**：每个 ADR 有无标准 Status 头（见下）；被取代 / 证伪的是否标了历史；**「被取代」链双向性做机械差集**——凡 Status 头出现 `Superseded-by NNNN` / `Partially-superseded-by NNNN`，NNNN 那篇必须 grep 得到旧编号，缺即报反向链缺口。
- **文件名合规**（机械项，`ls` 一遍）：`docs/` 下全部文件名英文 kebab-case；`docs/adr/`、`docs/journey/` 带四位编号且各自不复用；例外只有约定俗成的全大写入口文件（判据在 CLAUDE.md 文档纪律「文档文件名」条）。

### Status 头（第二层的配套：枚举、判定与连带审计）

格式：`> **Status:** <枚举> · <superseded-by NNNN 若有> ·（<Partial 注解若有：结论存什么 / 立场变什么>）`，头本身是每个 ADR 开头一行。

枚举：**Accepted**（决策仍完整有效、当前 code 就这么实现，或有意 defer 但决策不变）· **Superseded-by NNNN**（整个决策被后续 ADR 取代、已不作数，保留作决策史）· **Partially-superseded-by NNNN**（核心结论 / 理由仍成立，但某操作性立场或实现细节被后续反转；注解须写清「结论存什么、立场变什么」）· **Draft**（前瞻 / 尚未实现的设计）· **Historical**（纯决策史，所述机制已不存在）。

判定方法：Read 全文看自述 → 查**编号更大的引用源**有没有明说取代它（核心结论 vs 操作立场，只有后者变 = Partial）→ 必要时对照 code → 拿不准标 UNCERTAIN 交人定，别硬猜。

**连带审计——Accepted 必自包含**：一个 ADR 标（或本次将改为）Accepted / 冻结态时，顺带查它是否已清掉 journey 引用与裸 WP 编号（Draft 可暂留、Accepted 必清），发现即为到期未还的债、必修（内联证据 + 换自明描述，见 DEADLINK 引用方向违规条）。这是该纪律唯一的定期审计点：执行 = 对 ADR 与 CONTEXT 一次 grep，不单列步骤；它承担「Accepted 必自包含」的防误伤职责，零命中不作退场依据。

### 第三层：按事实族横切（【强制】，与按文档分片正交）

分片按文档聚类只能抓片内矛盾，cross-ADR 层只做结构；「同一事实在两个分片各写一份且已漂移」——正是 REDUNDANCY 与跨文档 CONTRADICTION 的主形态——前两层都照不出。本层换轴：**按事实族切、不按文档切**。

- **族清单每轮从真值集类别现列**（不照抄固定清单）：退出码语义 / 状态枚举与终态 / 事件类型与字段 / CLI 子命令与 flag / 目录树与模块清单 / 版本·模型 ID·依赖锁 / 命名契约（prefix、SSM 路径、表名、镜像 tag）/ 角色术语 / 数字类（超时、并发、保留期、票数）——本质是 CLAUDE.md 文档纪律「枚举型内容」那条的族级视图；新 ADR 每引入一个机读面，族清单随之加一行。
- **每族一个审计员**：grep 全部项目文档里该族的每一处提及，横向比对一致性并**指认权威位置**（ADR 的决策段 / code 真值 / 生成副本的源）。不一致报客观类（对抗验证同第一层）；「完整副本且已漂」报 REDUNDANCY，修法 = 压成带指针的简短重述、不是删信息（红线「有意重复 ≠ 冗余」仍适用——带指针的简短重述放行）。
- **产出槽**：每族一条记录——权威位置 + 提及处清单 + 一致 / 不一致判定；CONTEXT.md 若有词条覆盖该族而无 ADR 指针，报一条；没有词条不报——词表只收概念、不为事实族立条（ADR 0045 决策八）。空槽 = 本层未执行。

## 落地纪律

- **客观类（矛盾 / 过时 / 坏链接）直接改**——它们有唯一正确答案；**例外 = STALE 第③类**，不改文档、报人裁定。
- **主观类（压缩 / 重组 / 施工叙事提纯 / 口吻）先出报告待人批**。**搁置也要落锚**：对某候选判「保留」时，理由须写成具体受保护要素的引用（指名 + 定位），不许「边界情况 / 差不多」搪塞——防「浮出 → 搁置 → 形式满足而净提纯恒零」。
- **落地机制**（多轮验证过的形态）：按**文件归属**分组并行修补，每个文件只属一组；每组落完由独立视角**逐 hunk 复核**（改法是否按报告落、受保护要素是否丢、有无元评论泄漏、术语是否规范、有无越报告范围顺手改），复核意见落回；**改法依赖裁定或待批提案的客观条目跳过并登记**，随该裁定一起落；退役名跨多篇的处理按上 TONE 术语面条。落完统一跑：契约副本重渲染并 `--check`、图源指纹、相对链接与锚点可达、全部单测与文档护栏。
- **待批报告**：默认对话内呈报；人要异步审时落 `docs/journey/`（过程产物，批毕落改吸收即删）。**骨架固定**，便于审批：① 基线（锚点 → HEAD、审计集动 / 没动清单、各类计数）；② 请裁定（STALE ③ 与其它决策项，**每项带复盘方倾向与理由**，编号可一句话回）；③ 可直接改（CONFIRMED 客观类，按文件分组、每条 = 文件:行 · 类别 · 一句问题 · 逐字改法）与已驳回（REFUTED）/ 存疑（UNCERTAIN）；④ 提纯提案（只列红线复核通过的，approve_reduced 用缩小后改法）；⑤ 主观发现（引原句 + 改写句）；⑥ 具名提纯审计记录；⑦ 事实族横切记录；⑧ Status 头与反向链；⑨ 方法复盘草稿。同一处多来源合并为一条、标来源；长证据放条目末尾括号里。

## 产出与提交

- 客观类改完给 diff 汇报；裁定与主观类批准后再改。提交按批：客观批（含报告入库）→ 裁定批 → 落地批（提纯 + 主观 + 连带，删报告）；code 侧连带（如 VIOLATES_ADR 修正）与文档分开 commit。
- commit message 说清各类各改了几条、守了哪些护栏，并记「本轮提纯浮出 N 条 / 纠错 M 条」——N 必须等于具名审计记录里提案条数的机械汇总（不许自由填报），只记条数、不记比值、不设健康区间（N = 0 配扎实判无记录是完全合格的结果）。**落地提交**（删待批报告的那个）说明末尾以 git trailer 形式带 `Doc-Health-Round: N` 与 `Doc-Health-Records: <被删报告路径>`——两行与 `Co-Authored-By` 同在最后一个段落（trailer 块中间不能有空行），是下一轮跨轮沿用的锚点。
- **方法复盘（落地提交说明里、与 trailer 同处，三五行不写散文）**：本轮哪些规则抓到了真问题（点名规则 + 一条实例）、哪些规则跑了但零命中或全是误报、执行卡在哪、由此提议的规则增删改。这是「动规则」的**唯一入口**——复盘只按现有规则找问题、不就地改规则：下一轮开局按锚点读到它，提议的规则变更作为该轮第一份待批交人，批了才改方法文档。**退场判据**：连续两轮零命中、且不承担防误伤职责的规则，提议合并或降为一句提示；新增规则必须写明它防的失败形态。

## 已知失败形态（规则的来历，只读）

各条规则为什么这样写，来自历轮亲历；写在这里而不写进规则里，规则才不长成施工史。

- 枚举差集：目录树、CLI 选项表、ADR 接口清单都曾漏列，散文读着没问题、逐条对真值集才现形。
- 假真值集：默认 locale 把 CJK 词表折叠掉过半，差集「跑了」却漏掉一半命中、零报错。
- 取锚点：`grep -m1 .` 恒命中 HEAD，区间退化成本轮自己的提交，全部 ADR 被判「可沿用」，提纯审计形式满足而实际零执行。
- 层读：层数多的长文件全量 `git log -p` 把并行审计员撑到停摆，限读后即过；层读本身也产出结论——曾证实某节与闭合节同批写入、推翻「它是沉积」的猜测。
- 红线复核：被否的提案全落在「反模式实例 / 带指针的有意重复 / 历史框定」三种误判；若照原提案执行会删掉决策理由、被拒方案护栏、唯一证据。
- 提纯挤出：曾有整轮发现全是纠错、零提纯，故提纯审计设为强制并配具名产出槽。
- 反向链：新 ADR 收口时只写「我影响了谁」、漏登「我取代了谁」，一轮三处同犯而两篇头都自陈「反向链已落」。
- 术语面误报：把口头语表当退役词表、把完整术语名的 Avoid 推及前缀、把词条「句末至多一个 ADR 指针」的上限读成必填；只改一处退役名造成新的跨篇不一致。
- 沿用退化：某篇连续三轮沿用后，依据退化成「引用链 + 一字未动」。
- 事实族横切：曾抓到的几条跨文档矛盾，全靠某个审计员恰好两边都读了，换一种聚类就漏。
- 图源无人区：图源既非 markdown 也非 code 注释，两侧任务都不收，直到显式列进覆盖范围。
